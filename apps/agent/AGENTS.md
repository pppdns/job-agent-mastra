# apps/agent — Mastra server

- Entry: `src/mastra/index.ts` (agents, storage, observability, server auth, routes). Register agents in code: file-based discovery isn't used.
- Env: `src/env.ts` validates at import and fails fast with variable names only; empty strings count as unset. `LLM_MODE=mock` swaps in the deterministic model from `src/mastra/models.ts`: it echoes the user; calls `ingest_listing` for a bare URL or a message starting with `Listing:`, then `save_job_draft` after a saved listing; `Remember: x` proposes adding x; `For this chat: x` writes working memory; `Profile?` / `Local?` echo what the system prompt contains; `Slow: …` streams for ~4.5 s (refresh/stop tests); Observer/Reflector prompts get a fixed `<observations>` reply; `Research: <topics>` calls `research_company`, and the researcher searches, reads the top result and records one claim. `Listing: <title> at <company>, …` passes title and company (tools only when offered, so title generation stays text).
- Instructions are async: `BASE_INSTRUCTIONS` + the approved profile from the DB (`formatProfile`, with version and fact handles like `[fact:f7]`; `get_job` also shows handles) + while the profile is thin (no hard requirement or < `THIN_PROFILE_FACTS` facts) `profileLearningHint`, which has the copilot end assessments with 1–2 preference questions that decide that job + today's local date last (`todayLine`, also in the researcher), rebuilt every turn.
- Tools: `src/mastra/tools/`, registered on the agent under snake_case names: `ingest_listing` (a URL of a saved job returns `already_saved` without fetching; `refresh: true` re-reads), `save_job_draft` (no approval; each save is the job's new current version), `propose_profile_change` (propose only; approval happens in the web app), `find_saved_jobs` (text and/or pipeline `status`; archived jobs only with `includeArchived` or a closing status), `get_job` (`includeListing: true` re-parses the latest stored listing for re-assessment), `set_job_status` (the user's pipeline status, no approval; `statusChangeRefusal` refuses it unless the latest user message names the status, isn't pasted content, and no listing/web text was read in this turn), `research_company` ([src/research/AGENTS.md](src/research/AGENTS.md)), `rescore_jobs` ([src/rescore/AGENTS.md](src/rescore/AGENTS.md)). Mastra adds `updateWorkingMemory` (thread-scoped, "this chat only" notes). Rule violations from `@copilot/db` (`AssessmentError`) are returned as `{ ok: false, error }` so the model can correct itself. Listing ingestion: [src/ingest/AGENTS.md](src/ingest/AGENTS.md). Web provider clients (Tavily, Firecrawl) in `src/web/providers.ts`, selected by `src/web/active.ts`; `WEB_MODE=fixture` uses `fixtures/web/` instead. Without `TAVILY_API_KEY`, URLs fall back to asking for a paste and research is unavailable.
- App tables: `getAppDb()` (`src/mastra/app-db.ts`) migrates once per process on first use; data access goes through `@copilot/db` functions only.
- Models come from `getModel("main" | "fast")`, which returns the native `@ai-sdk/gateway` provider. Don't use `vercel/...` router strings (they lose cache/reasoning usage).
- Server: 127.0.0.1 (`AGENT_HOST`; Fly uses `::` so `fly proxy` reaches Studio over the private network), `AGENT_PORT` (default 4111; per checkout via `scripts/ports.sh`), every route behind `SimpleAuth` with `AGENT_SHARED_SECRET`. Chat runs are durable (`copilotAgent` = `createDurableAgent(copilotBaseAgent)`): `POST /chat` starts a run and records it in `app_runs`, `GET /chat/:threadId/stream` re-observes the active run (or 204), `POST /chat/:threadId/stop` aborts it (`src/mastra/routes/chat.ts`; chunks are sanitized there). Client disconnects never stop a run. The route sets `THREAD_CONTEXT_KEY` in the request context so instructions can inject this chat's pending approvals; `/threads/:threadId/ui-messages` returns a thread's history as AI SDK v7 UI messages.
- Memory: `src/mastra/memory.ts` (`chatMemory`). One thread per chat; only that thread's history (compacted by Observational Memory, threshold `OM_MESSAGE_TOKENS`) and thread-scoped working memory are recalled, so chats can't see each other. Durable user facts live in the approved profile (app tables), never in Mastra memory. `mapUserToResourceId` pins all memory access to the authenticated user's resource; Mastra's built-in `/api/memory/threads*` routes then filter and 403 by resource. Custom routes must read `MASTRA_RESOURCE_ID_KEY` from the request context and check ownership themselves.
- Storage: `createStorage()` (`src/mastra/storage.ts`), a composite store: libSQL at `resolveDatabaseUrl()` (same file as app tables) for memory and everything else; DuckDB at `resolveObservabilityPath()` (`data/copilot.duckdb`, derived from `DATABASE_URL`) for traces, logs and metrics. Studio's logs and metrics pages and its trace token/cost columns don't work on libSQL. DuckDB locks its file, so only one process can open it.
- Only one `mastra dev` can run per project; `mastra build` is blocked while it runs. `mastra build` also fails at its install step: the Mastra deployer can't parse pnpm 12's two-document `pnpm-lock.yaml`. Builds aren't used (local dev only). `mastra dev` loads `.env`, so the e2e config blanks provider keys to stay offline.
- Usage accounting: [src/usage/AGENTS.md](src/usage/AGENTS.md). Any new model call outside an agent's steps must be metered (`meteredModel` or a hook), or the panel will undercount.
- Provider calls retry via `withRetry` (`src/web/retry.ts`): only `RetryableError` (network, timeout, 429, 5xx), max 2.
- Scorers, datasets and `pnpm eval`: [src/evals/AGENTS.md](src/evals/AGENTS.md). Copilot turns are scored live only with `LLM_MODE=live`.
- Look up APIs in `node_modules/@mastra/*/dist/docs/` (see the `mastra` skill) before writing Mastra code.
