# apps/web — Next.js UI

- The browser only calls same-origin routes. `src/server/agent.ts` (`server-only`) adds the shared secret and calls the agent. `src/app/api/chat/route.ts` validates `{ threadId, message }` (`src/lib/chat-schema.ts`), builds the agent body in `src/server/chat-body.ts`, and streams `/chat` through; never forward client JSON to the agent.
- Chats: `/c/[threadId]` (chat id = Mastra thread id); `src/proxy.ts` redirects `/` to a fresh UUID. Thread list/history/rename/delete go through `src/server/threads.ts`; mutations are server actions in `src/app/actions.ts` that call `refresh()`. Archiving is `archivedAt` in the Mastra thread metadata (`src/lib/thread-archive.ts`; PATCH replaces metadata, so always merge). Archived chats stay fully usable, and `POST /api/chat` unarchives on send.
- Messages: user text in a `Bubble`; assistant text via Streamdown with images and raw HTML disabled (an injected reply must not make the browser fetch URLs); tool parts as `Trace` rows (`src/components/tool-trace.tsx`); `research_company` renders its `data-research-progress` parts as a timeline plus a findings panel (`research-trace.tsx`, `evidence-list.tsx`); `rescore_jobs` renders `data-rescore-progress` plus a results list (`rescore-trace.tsx`). `globals.css` has an `@source` for Streamdown's classes: restart `next dev` after changing `@source`.
- App tables: server code reads/writes through `@copilot/db` via `appDb()` (`src/server/db.ts`). libsql is synchronous, so pages call `await connection()` before reading (inside `<Suspense>`), or the query would run at prerender time.
- Approvals exist only for profile changes the copilot proposes in a chat: `ApprovalCard` reads state from `GET /api/approvals/[id]?threadId=` (404 for other chats) and decides via the `decideApprovalAction` server action with the payload hash it displayed. `/profile` edits are the user's own and apply right away (`editProfileAction` → `editProfile`, with the profile version the page showed; recorded under thread `profile-page`). Job assessments need no approval: `/jobs/[jobId]` shows the current version ("Assessment vN") and earlier versions under a "Version history" toggle that starts closed. Old chats may still contain `propose_job_snapshot` calls; they render as a plain trace row. `/jobs` is a compact table (`aria-label="Jobs"`) with URL state `?tab=active|<status>|archived&q=&sort=latest|fit` (`src/lib/job-list.ts`; Active = not archived, status tabs exclude archived jobs; `q` uses FTS via `searchJobIds`; best fit = fit level, then verdict, then fewer hard conflicts). The title link covers the row; `JobStatusMenu` (also on the job page) sets status / (un)archives via `setJobStatusAction` / `setJobArchivedAction`. It shows a "Re-score" button when active jobs are stale (`startRescoreAction` starts the run in a new chat, then redirects there).
- Assessments at a glance: `assessment-visuals.tsx` holds the shared pieces (verdict badge, fit meter, signal chips, evidence badge, summary header) and the tone map. Colors come from semantic tokens in `globals.css` (`success`, `warning`, `info`, `destructive`, plus muted); use these, not raw Tailwind colors. A successful `save_job_draft` renders as `AssessmentCard` ("Saved · vN") (from the validated tool input) instead of a trace row; the copilot is told to keep its prose short because of it. Its "Research next" buttons (`research-suggestions.tsx`, topics from `suggestedResearchTopics`) send `researchRequestText` in the chat (disabled while a reply runs); on the job page the same buttons call `startResearchAction`, which starts the research in a new chat like Re-score.
- Durable runs: `useChat({ resume: true })` reconnects via `GET /api/chat/[threadId]/stream` (204 when nothing runs); Stop calls `POST /api/chat/[threadId]/stop` before closing the stream. Observational Memory `data-om-*` parts: compaction ones render as a line (`compaction-line.tsx`), the rest are hidden.
- Technical panel: `technical-panel.tsx` (sheet in the chat header) reads `GET /api/threads/[threadId]/usage` (`threadUsage` + approvals from `@copilot/db`). Studio links: `${AGENT_URL}/traces?traceId=…` (`serverEnv()` derives `AGENT_URL` from `AGENT_PORT`).
- Next keeps visited pages mounted but hidden (React Activity): a chat keeps streaming when you navigate away, and e2e locators must filter `{ visible: true }`. e2e runs with `WEB_MODE=fixture`. Verify UI in a foreground browser: a hidden built-in browser pane can leave streamed pages on their Suspense fallback. Wait for a reply to finish before sending the next message: the input ignores submits while busy.
- `src/server/env.ts` validates server env lazily, so `next build` doesn't need secrets.
- Cache Components and Partial Prefetching are on (Next 16.4 defaults). Read `node_modules/next/dist/docs/` before using data-fetching or caching APIs.
- UI: shadcn/ui (Radix Nova). `src/components/ui/` and `src/hooks/use-mobile.ts` are CLI-owned (don't edit; `ui/` is excluded from Biome). `SidebarMenuSkeleton` uses `Math.random()`, which breaks prerendering: use `Skeleton` with fixed widths; add or update with `pnpm dlx shadcn@<version> add <component>`. Chat composition follows the `shadcn` skill (`rules/chat.md`).
- Tests: Vitest for units; Playwright in `e2e/` (`playwright.config.ts` starts an isolated mock stack using system Chrome). Spec files share one database; `rescore.spec.ts` re-scores every stale job, so it runs in its own project after the rest.
